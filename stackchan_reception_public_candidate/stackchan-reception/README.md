# 宛名を読んで、連絡先と行き先を案内する受付ロボット

Physical AI応用1講座 最終課題。OmniCampus ID：86611。

StackChan K151で配達の問い合わせを受け、宛名を撮影して架空の名簿と照合し、内線番号と建物の方向を案内する試作です。読み方が分からない名前を画像で確認する場面を実演しています。

## 実演した流れ

1. 「森川さんへの荷物」という依頼に、下の名前か所属を尋ねる。
2. 読み方が分からない宛名を、本体のプレビューに合わせて撮影する。
3. 「森川 将大」を名簿と照合し、読みと所属を示して宛先を確認する。
4. 架空内線8102を一桁ずつ読み、電話がある想定の方向へ首を向ける。
5. 模擬通話後に行き先を尋ねると、研修棟への道順を案内する。

施設・職員・所属・内線はすべて架空です。自動発信、在席確認、入室許可、荷物の受領は行いません。

## 自作部分と使用した基盤

- **本体ファームウェアの改修**：撮影前のライブプレビュー、緑枠、タッチ撮影ボタンを追加。撮像・画像変換・送信・サーボ制御には既存処理を使っています。
- **受付MCP**：用件・宛先・確認状態を管理し、名簿照合と確認後の案内を行います。訂正された古い確認は再利用しません。
- **方向の対応**：来訪者視点の左はyaw=+45、右はyaw=-45。番号の聞き直しでは首振りを追加しません。
- **既存サービス**：小智AI（XiaoZhi AI／xiaozhi.me）を音声認識・画像理解・対話・音声合成に利用しています。AIモデルの学習は行っていません。

## 起動方法

Pythonの仮想環境を作成し、依存をインストールします。PowerShellの場合：

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe reception_server.py
```

MCPクライアントから、最後のコマンドをstdioサーバーとして起動します。小智AI側との中継接続には、利用する環境での設定が別途必要です。接続先・認証情報は同梱していません。`personality.txt`はクラウド側のPersonality欄へ全文設定します。

### 公開する5ツール

| ツール | 用途 |
|---|---|
| `advance_reception` | 配達・面会・内線照会・画像照合・追加質問の共通入口 |
| `get_center_info` | 施設概要と受付時間 |
| `get_place_guidance` | 登録された場所・建物の道順 |
| `get_training_guidance` | 登録された研修の案内 |
| `get_facility_policy` | 飲食・喫煙等の施設ルール |

以前の候補検索や文書受付の個別入口は、MCPに登録しません。内部の照合関数は回帰試験の対象として残しています。`advance_reception`が返す`case_id`は同じ応対で引き継ぎ、利用者が変わったら空欄で開始します。

## 確認方法と範囲

```powershell
py -B -m unittest discover -p "test_*.py"
```

284件の単体試験で、氏名照合・確認と訂正・画像と音声の情報の区別・追加質問・方向変換・公開ツールの登録を確認しています。テストは認識精度やクラウドの応答を測定するものではありません。

撮影した一件では宛先確認から道案内まで進みましたが、同じ案内の重複が残っています。Personalityへの指示だけで、撮影許可・ツール呼出し回数・正面復帰の完了を強制する仕組みではありません。個別の対策候補や検証途中のソースは公開対象から分けています。
